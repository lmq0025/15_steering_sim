### 2.1 计时口径与原始问题

用户报告的0→10°工况为车速5 km/h、6 s/deg、指令60 s、保持10 s、物理总时长70 s，电脑耗时约230 s。**230 s是用户报告值，不是本轮同进程复测值**。历史阶跃约5.3 s同样不能直接与70 s斜坡比较，因为积分的物理时间不同。

- 模拟物理时长：模型时间跨度，不是电脑耗时。
- `rk_stage_wall_s`：原始`_stage`函数调用的累计墙钟，覆盖状态相关道路负载和液压导数计算，不含边界记录复制；**不是完整RK4循环的独占墙钟**。
- `runtime_s`：联算核心边界，包含参考准备、积分循环、控制和原记录整理。
- `service_runtime_s`：完整正式服务，含初始化、分析和常规结果写出。
- `benchmark_wall_s`：测量外壳的服务调用墙钟；边界复制在此范围内，结束后的验收NPZ压缩不计入。
- 正式服务新增低侵入`performance_timing.rk4_wall_s`：四个状态相关RHS子阶段及RK4状态更新，**不含PID和记录行**；`control_wall_s`、`recording_wall_s`和`integration_loop_wall_s`分别记录原控制、记录及整个时间循环。它与旧`rk_stage_wall_s`范围不同，不混称一个指标。

完整基准额外逐0.5 ms保存22状态和四个阀命令，用于保持段速度、阀芯和压力峰值的全过程核对。该验收记录器存在开销；有/无记录器及历史环境差异应清楚标明。最终日常GUI耗时需要单独实测。
