## 2. 源码结构复盘

`HydraulicPlant` 把单缸的机械质量、双腔压力和阀芯状态组成 5 维状态，并通过内部 RK4 子步推进。`ExcavatorArm` 则把四个关节、四个速度、三缸与回转马达的双腔压力/阀芯、供油母线压力组成 21 维状态，把具体推进委托给 `ArmStepper`。

```text
controller --obs/ref--> command
     |                     |
     | no plant reference  v
     +--------------- ExcavatorArm
                         |-- PlanarLinkage + CylinderMap
                         |-- pump + supply manifold + LUDV
                         |-- valve/cylinder/motor equations
                         `-- ArmStepper registry
                              |-- IMEX
                              |-- TLM-like implicit coupling
                              `-- constrained IMEX
```

这两条路径并不完全统一：单缸 `HydraulicPlant` 自带固定 RK4；全臂模型使用可替换 stepper。参数也分散在 `core.params` 与 `params.excavator`，部分求解器保护参数仍为函数内常量。

## 3. 值得直接借鉴的软件架构

1. **物理核心不依赖 GUI。** 上游核心依赖集中在 NumPy，记录器/可视化通过回调或观测字典接入。这种依赖方向适合保留。
2. **控制器不持有 plant。** `BaseController` 只消费观测并产生指令，PID、前馈 LUT、标定和多轴组合可独立测试。我们的接口进一步显式传入 `reference`，冻结为 `measurement + reference + dt -> command`。
3. **统一生命周期。** `reset`、`observe`、`measure` 和 `step` 让复现实验、真值诊断、传感器信号及推进动作语义分离。
4. **求解策略对象与工厂。** `ArmStepper` + `create_stepper` 允许 IMEX/TLM/约束方案 A/B 对照，避免把求解算法散布在顶层模型中。
5. **状态集中。** 全臂 21 维状态由顶层集中管理，执行器几何量作为 `q, q_dot` 的派生量，避免缸位移重复积分造成漂移或代数不一致。
6. **非线性特性可开关。** 死区、滞环、阀动态、摩擦、泄漏、变容积和噪声开关适合做消融测试；但本项目会用参数/模型组合而非大量全局布尔开关来控制复杂度。
7. **测试分层思想。** 上游同时有方向性、边界、解析基准、尺度律、守恒趋势、控制性能和不同 stepper 对照。这种验证金字塔值得借鉴。

## 4. 值得参考的液压方程

以下只作为候选方程和符号约定，进入本项目 R03 前仍需由转向液压原理图、元件数据和 AMESim/试验结果确认。

### 4.1 四通阀孔口流量

上游使用

```text
Q = K_v |x_v| sign(Delta p) sqrt(2 |Delta p| / rho)
```

并按阀芯方向分别连接 `P_s -> A, B -> P_t` 或 `P_s -> B, A -> P_t`。值得参考的是四象限符号处理、供回油分别计算、死区后重映射和一阶阀芯动态；不可直接沿用的是单一线性开口面积、固定油温/密度、无流量力、无阀口几何分段、无阀芯二阶电磁动态等简化。

### 4.2 双腔连续性

单缸模型采用

```text
dP_a/dt = beta_e / V_a(x) * (Q_a - C_leak(P_a-P_b) - A_a v)
dP_b/dt = beta_e / V_b(x) * (Q_b + C_leak(P_a-P_b) + A_b v)
V_a = V_dead_a + A_a x
V_b = V_dead_b + A_b(stroke-x)
```

这体现了有效体积模量、位置相关容积、活塞扫掠流量和跨腔内泄漏，是转向缸模型的正确起点。后续必须核对单双出杆结构、管路容积、软管膨胀、含气量、温度、外泄漏和转向机构的实际行程定义。

### 4.3 力与力矩转换

缸净液压力以 `F_h = A_a P_a - A_b P_b` 计算，再通过缸长对关节角的雅可比 `tau = (dx/dq) F_h` 映射；马达以 `T_h = D_m(P_a-P_b)/(2 pi)` 计算。功率共轭变量及雅可比映射思想值得保留，但转向系统应使用其真实齿条、摇臂、转向节和轮胎几何，不能使用挖掘机三角缸映射参数。

### 4.4 供油与压力动态

变量泵排量流量、恒功率限制、母线容腔

```text
dP_s/dt = beta_e/V_line * (Q_pump - sum(Q_demand) - Q_relief)
```

以及显式溢流支路的思想可参考。LUDV 按需求同比例缩放是挖掘机共享泵的特定策略；是否适用于本项目取决于实际转向泵、优先阀、蓄能器及其他负载原理图。

### 4.5 摩擦和非理想因素

Stribeck + Coulomb + viscous 并以 `tanh` 平滑零速，可用于早期数值模型；backlash play 算子、传感器噪声与量化也可作为可替换部件。它们不是经过本项目设备辨识的模型，静摩擦粘滞、密封摩擦、齿隙及轮胎回正力矩必须独立确认。

## 5. 只适用于挖掘机、不能迁移的机械模型

- `PlanarLinkage` 固定为动臂/斗杆/铲斗 3-DOF 平面串联链，质量矩阵、重力项和质心雅可比都建立在该拓扑上。
- `CylinderMap` 的三角形铰点几何、每个缸只对应一级相对关节角，以及 `tau_i=(dx_i/dq_i)F_i` 的对角式映射不代表转向梯形机构的交叉耦合。
- 铲斗尖端地面贯入的弹簧阻尼“土壤力”与转向系统无关。
- 独立回转自由度、液压马达、回转软限位和 swing brake 与车轮转向机构无关。
- boom counterbalance/over-center valve、四执行器 LUDV 抢流和重力平衡预充压力是挖掘机场景假设。
- 固定三连杆重力模型不能代表轮胎侧向力、主销后倾/内倾、磨胎半径、阿克曼几何、拉杆柔度、齿条/转向器传动、路面扰动与车辆横向动力学。
- `soft_limit_torque` 中的刚度/阻尼常量及多处经验阈值不能作为转向限位或接触参数。

可借鉴的是“用广义坐标、质量矩阵、约束残差、正运动学和执行器雅可比表达机械系统”的方法，而不是任何挖掘机参数、自由度布局或载荷方程。

## 6. 控制器层如何与物理模型解耦

上游的核心优点是控制器只接收 `obs` 字典，不导入或持有 `HydraulicPlant/ExcavatorArm`。`reset` 清除积分、滤波、限速和滞环记忆；`diagnostics` 只为记录，不参与控制。轨迹、前馈、PID 和标定也被拆开。

局限是字符串键和数组下标（如 `q[0]`）缺少静态契约，且 setpoint 有时藏在控制器可变属性里。我们的 R01 改为强类型 `Measurement`、`Reference`、`Command`，统一调用 `Controller.step(measurement, reference, dt)`。控制器仍不得持有物理模型；任何模型知识应通过显式配置、前馈策略或估计器注入。

## 7. `step/reset/observe/measure` 的价值

- `reset(state)`：清空状态和历史记忆，支持确定性重复试验、批量标定和回归测试。
- `observe()`：返回无噪声真值和诊断量，用于物理调试、守恒分析及后续质量评估。
- `measure()`：只暴露传感器可见量，并可注入噪声、偏置、量化和采样效应；控制器不应读取真值后门。
- `step()`：适合作为面向场景的离散推进门面和控制采样边界。

对本项目的关键约束是：物理模型必须另外提供无副作用的连续 `rhs/derivative`。顶层 `step` 应由耦合系统和 solver 驱动，不能永久固化为“液压一步再机械一步”的显式串行算法；离散控制器可以保留采样 `step`。

## 8. IMEX/TLM 等求解器架构评估

### 值得借鉴

- `ArmStepper` 抽象基类、名称注册表、统一输入输出和 stepper 私有状态 reset。
- 对刚性腔压使用局部隐式处理，对慢机械量/阀芯/母线采取不同策略的 IMEX 思想。
- `_implicit_pressure_update` 对双腔泄漏耦合形成 2x2 线性系统，减少显式压力积分的稳定步长限制。
- TLM stepper 将腔压写成速度的仿射函数，液压刚度/阻尼进入机械速度线性系统，从而在同一个子步内体现双向反馈。
- 不同算法使用相同顶层状态与诊断输出，利于收敛性和 A/B 对照。

### 不应照搬或锁死

- `IMEXStepper` 仍是专门针对固定 21 维挖掘机状态布局的手写算法，不是通用 ODE/DAE 求解器。
- 其 TLM 是“腔体特征阻抗/稳态隐式消元”式近似，代码中没有通用管路波传播拓扑、传播延迟队列或任意网络连接，不能把名称本身当作高保真传输线证明。
- 阀芯和供油母线仍显式推进，孔口关系在当前点线性化；强非线性、换向和事件附近需要步长收敛检查。
- 约束 IMEX 通过阀芯阈值硬锁关节、冻结/重算压力，是稳定化策略，不是严格液压闭锁 DAE 的物理解。
- 多处压力、体积和限位硬钳位会丢弃能量并造成非光滑事件；这对鲁棒运行有用，却限制守恒精度和梯度/灵敏度分析。

因此本项目冻结通用 `Solver.solve(rhs, t_span, y0, evaluation_times)`，提供显式定步长和 SciPy `solve_ivp` 适配器，并预留 `BDF/Radau`。未来若约束确实形成 DAE，应扩展质量矩阵/残差/Jacobian 接口，而不是把所有约束伪装成 ODE 钳位。

## 9. 精度与高保真局限

1. 默认参数多为合理量级或工程假设，未见与本项目甲方设备一一对应的参数溯源、置信度和版本化标定记录。
2. 液体采用集总、等温、常密度/常体积模量近似；没有热平衡、粘度温变、含气析出/气穴动力学和完整软管壁顺应性。
3. 阀模型以静态孔口 + 一阶阀芯为主，缺少电磁、流量力、阀芯摩擦、制造公差和频率相关动态。
4. 泵模型是排量/恒功率流量上限，未完整表达转速源、扭矩、效率图、压力补偿器和脉动。
5. 管路只有母线等效容积；没有局部分布参数、波阻抗网络、弯管损失、局部惯性和真实连接图。
6. 摩擦以平滑 Stribeck 代替真实静摩擦粘滞；低速爬行和换向精度有限。
7. 机构是刚性二维集中参数模型；忽略结构柔性、间隙、三维几何、轴承/衬套和真实接触。
8. 土壤、平衡阀、回转制动和软限位包含经验模型或阈值，主要服务数值稳定与场景合理性。
9. 压力下限、溢流上限、体积下限和位置限位采用硬钳位，能量可能无记录地消失；部分测试明确接受此近似。
10. 缺少针对电液转向的轮胎/路面载荷、车辆速度相关回正力矩、转向梯形、助力特性和故障工况。

## 10. 为什么现有测试不能证明“模型误差 ≤10%”

上游测试多数证明的是实现自洽性，而非对真实设备的外部有效性：

- import/有限性/方向/边界测试只说明代码不崩溃且符号大致合理。
- 尺度律和解析基准使用与实现相同或高度相关的简化方程，属于代码验证（verification），不是实物确认（validation）。
- IMEX 与 TLM 对照只能说明两种离散化趋向同一内部模型；共同的建模偏差不会被发现。
- 控制跟踪误差衡量“控制器跟踪本仿真 plant”的性能，不是仿真对实测的模型误差。
- 断言容差并非统一 10%；源码中可见 15%、20%、25%、30%、45%、50% 以及仅检查趋势/范围的条件。
- 若标定数据由同一仿真模型生成，会形成闭环自证，不能替代独立 AMESim 或台架数据。
- 测试没有覆盖本项目的结构、参数域、输入谱、温度、载荷、传感器链与验收指标。
- “误差 ≤10%”尚需先定义观测量、误差范数、时间窗、工况矩阵、数据不确定度和通过准则。

要形成直接证明，至少需要冻结客户构型和参数，使用独立数据集，在规定工况下比较压力、流量、位移/角度、速度、力/力矩与功率/能量，并报告时间对齐、滤波、稳态/瞬态误差和置信区间。
