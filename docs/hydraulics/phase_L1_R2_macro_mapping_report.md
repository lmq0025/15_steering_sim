# PHASE L1-R2 宏观液压物理映射修订与 Amesim 配对恢复报告

## 结论

PHASE L1-R2 完成，但验收结论为 **FAIL / NOT READY**。本轮成功恢复了 S0、S1、S2 三个 Amesim 隔离副本场景，修正了四泵独立转速接口、冗余阀独立支路及交叉工作口映射，并使供油代数求解器显式验证流量守恒。受保护的 `qh1_1.ame` 与 `qh1_1_MCP_AUDIT.ame` 未修改。

## S0 可比性复核

泵流量、阀输入、液压缸端口压力的单位和符号可追溯；泵出口压力测点不能与 Python 的单一 `supply_pressure` 无条件等同。更重要的是，Amesim HJ020/HJ021 的 `x`、`v` 是机械端输入，而集中模型原来把它们作为局部质量状态并在 `F_load=0` 下积分。R1 的位移、速度和力误差因此混入了机械边界不一致。

R2 配对试验将 Amesim 的实际位移、速度和数值加速度作为显式 `prescribed_motion_by_alias` 边界输入。它们只用于隔离液压映射误差，明确标为 `MEASURED_AMESIM_BOUNDARY`，不计入独立预测成绩。详细定义见 `32A_S0_comparability_audit.csv`。

## 泵和阀支路映射

供油仍为两组：

- 前组：`pump01 + pump01_1`，服务 `dirvalve_6` / `actuator002`。
- 后组：`pump01_2 + pump01_3`，服务三对冗余阀和三个 HJ020 执行器。

泵组流量已由“泵数 × 代表速度”改为逐泵计算后求和，并保留旧按通道速度调用的兼容路径。新增按 alias 的泵速输入支持单泵关闭、组内不同转速和双泵同速。

每只冗余阀现在都有独立命令和独立孔口流量。IR V3 显示 `dirvalve_2/9/12` 的工作口相对对应主阀交叉连接；`dirvalve_6` 相对 actuator002 的 A/B 工作口也换位。代码在物理腔节点汇总流量，不增加阀状态。详见 `32B_pump_valve_branch_mapping.csv`。

## 供油测点与守恒

IR 证据区分了：泵出口、过滤器/冷却器两端、阀入口歧管、溢流入口和缸腔。当前模型只输出一个共址的 `pump_outlet_pressure/manifold_pressure`，因此 `SUPPLY PRESSURE MAPPING = FAIL`。此项不能通过继续调同一个 `R_eq` 修复；后续应先建立最小的两代数压力节点和可追溯的稳态损失分配，但本轮没有擅自改变状态结构。

旧求解器的 0–100 MPa 截断已移除。新求解器使用物理括区间及 `brentq`，零开度/单活动支路使用验证后的解析特例。每次返回都检查

\[
r_Q=Q_{pump}-Q_{valve}-Q_{relief}-Q_{other}
\]

并报告绝对、相对残差；无法括根或残差超限会抛出明确异常，不再静默返回边界值。工程容差为 `1e-9 m³/s` 或相对 `1e-6`，对应远小于额定泵流量的守恒误差。见 `32D_supply_balance_solver_audit.csv`。

## 配对结果

三场景均采用 1 s、0.5 ms 输出/积分步长、逐泵实测速度、逐阀实测命令、Amesim t=0 液压初值和显式机械运动边界。共形成 84 条变量级指标，其中 44 条满足“不是参数转移、不是标定目标、不是机械边界输入”的独立动态判定条件。

| 场景 | 独立动态量 | NRMSE ≤10% |
|---|---:|---:|
| S0 | 12 | 0 |
| S1 | 16 | 0 |
| S2 | 16 | 0 |
| 合计 | 44 | 0 |

主要偏差首先出现在供油压力/阀供流到缸腔压力的宏观链路。后组三通道 Python `pA` 可出现约 150–246 MPa 级误差，而 Amesim 宏观工作压力远低于此值；这不是泵排量或泵速误差。泵流量属于源码参数转移结果，不计作独立验证。位置和速度是显式机械边界，也不计作独立验证。
